> <h2 id="Go-flag-命令行参数解析">Go flag 命令行参数解析</h2>

Go 标准库 `flag` 用于解析命令行参数，使程序启动时可以从命令行接收端口、配置文件路径、运行环境、Debug 开关、Kafka Broker、数据库地址和日志级别等配置。

```go
package main

import (
	"flag"
	"fmt"
)

func main() {
	name := flag.String("name", "world", "your name")

	flag.Parse()

	fmt.Println(*name)
}
```

不传参数时使用默认值：

```bash
go run main.go
```

```text
world
```

传入参数时覆盖默认值：

```bash
go run main.go -name=Tom
```

```text
Tom
```

> <h3 id="flag.String">flag.String</h3>

`flag.String()` 注册一个字符串类型的命令行参数：

```go
func String(name string, value string, usage string) *string
```

| 参数 | 作用 |
| --- | --- |
| `name` | 参数名 |
| `value` | 默认值 |
| `usage` | 帮助说明 |

例如：

```go
serverName := flag.String(
	"name",
	"my-server",
	"server name",
)
```

程序由此注册 `-name` 参数。执行：

```bash
./server -name=gateway
```

解析后，`*serverName` 的值为 `gateway`。

### 返回值是指针

`flag.String()` 返回 `*string`，不是 `string`，因此读取参数值时需要解引用：

```go
fmt.Println(*serverName)
```

直接打印 `serverName` 得到的是指针地址，地址值每次运行可能不同：

```go
fmt.Println(serverName)
```

```text
0xc0000140a0
```

解引用后才会输出实际内容：

```go
fmt.Println(*serverName)
```

```text
my-server
```

> <h3 id="flag.Parse">flag.Parse</h3>

`flag.String()` 只负责**注册参数**，`flag.Parse()` 才会读取命令行参数并完成解析和赋值：

```go
port := flag.String(
	"port",
	"8080",
	"http port",
)

flag.Parse()

fmt.Println(*port)
```

```bash
./server -port=9000
```

执行流程：

```text
程序启动
    |
    |
flag.String注册参数
    |
    |
flag.Parse读取 os.Args
    |
    |
修改port变量
    |
    |
业务代码使用
```

### 不调用 flag.Parse

```go
func main() {
	port := flag.String(
		"port",
		"8080",
		"",
	)

	fmt.Println(*port)
}
```

即使传入参数：

```bash
./server -port=9000
```

仍会输出默认值：

```text
8080
```

因为 `-port=9000` 没有经过 `flag.Parse()` 解析。

> <h3 id="os.Args-与-flag">os.Args 与 flag</h3>

执行：

```bash
./server -port=8080
```

操作系统会将参数传给 Go 程序的 `os.Args`：

```go
[]string{
	"./server",
	"-port=8080",
}
```

`flag.Parse()` 默认解析 `os.Args[1:]`，将参数与已注册的 Flag 匹配后赋值：

```text
读取 os.Args

↓

匹配已经注册的flag

↓

赋值
```

> <h3 id="工程实践">工程实践</h3>

### 服务启动配置

目录结构：

```text
video-service

main.go
config/
```

`main.go`：

```go
package main

import (
	"flag"
	"fmt"
)

func main() {
	configFile := flag.String(
		"config",
		"./config.yaml",
		"config file path",
	)

	env := flag.String(
		"env",
		"dev",
		"runtime environment",
	)

	flag.Parse()

	fmt.Println("config:", *configFile)
	fmt.Println("env:", *env)
}
```

开发环境使用默认值：

```bash
./video-service
```

```text
config: ./config.yaml
env: dev
```

生产环境覆盖默认值：

```bash
./video-service \
-config=/etc/video/prod.yaml \
-env=prod
```

```text
config: /etc/video/prod.yaml
env: prod
```

### Kubernetes Deployment

```yaml
command:
- /app/video-service

args:
- "-env=prod"
- "-config=/etc/config/prod.yaml"
```

Go 程序注册并解析对应参数：

```go
env := flag.String(
	"env",
	"dev",
	"",
)

config := flag.String(
	"config",
	"",
	"",
)

flag.Parse()
```

启动后参数值为：

```text
env=prod
config=/etc/config/prod.yaml
```

### Kafka Consumer

```bash
./kafka-consumer \
-broker=10.0.0.1:9092 \
-topic=video_event \
-group=video-worker
```

```go
broker := flag.String(
	"broker",
	"",
	"kafka broker",
)

topic := flag.String(
	"topic",
	"",
	"kafka topic",
)

group := flag.String(
	"group",
	"",
	"kafka group",
)

flag.Parse()

consumer := NewConsumer(
	*broker,
	*topic,
	*group,
)
```

命令行参数适合在不修改代码和配置文件的情况下，为不同部署环境覆盖启动配置。

> <h3 id="flag.String-与-flag.StringVar">flag.String 与 flag.StringVar</h3>

`flag.String()` 创建变量并返回指针：

```go
port := flag.String(
	"port",
	"8080",
	"",
)

flag.Parse()

fmt.Println(*port)
```

`flag.StringVar()` 将参数直接绑定到已有变量：

```go
var port string

flag.StringVar(
	&port,
	"port",
	"8080",
	"",
)

flag.Parse()

fmt.Println(port)
```

| 对比项 | `flag.String` | `flag.StringVar` |
| --- | --- | --- |
| 返回值 | `*string` | 无 |
| 变量 | 函数内部创建并返回指针 | 绑定调用方已有变量 |
| 适用场景 | 局部、简洁的参数声明 | 参数需要绑定到结构体字段或统一管理的变量 |

> <h3 id="flag-与-Viper">flag 与 Viper</h3>

生产项目常同时使用命令行参数、环境变量和 YAML 配置。常见的预期优先级是：

```text
命令行参数 flag
        |
        |
       优先级最高
        |
        ↓
环境变量 ENV
        |
        ↓
配置文件 yaml
        |
        ↓
默认值
```

例如，配置文件定义：

```yaml
server:
  port: 8080
```

启动时传入：

```bash
./server -port=9000
```

如果程序使用 `pflag` 并通过 Viper 的 `BindPFlag` 绑定参数，或自行将标准库 `flag` 的结果合并到配置中，最终可得到：

```text
port=9000
```

即：

```text
flag > env > yaml > default
```

**注意：** 标准库 `flag` 与 Viper 不会自动关联；`BindPFlag` 面向 `pflag`，使用标准库 `flag` 时需要额外适配或在业务代码中处理配置覆盖关系。

> <h3 id="总结">总结</h3>

| 函数 | 作用 |
| --- | --- |
| `flag.String()` | 注册字符串参数并返回 `*string` |
| `flag.Int()` | 注册整数参数并返回 `*int` |
| `flag.Bool()` | 注册布尔参数并返回 `*bool` |
| `flag.Parse()` | 解析命令行参数并赋值 |
| `flag.StringVar()` | 将字符串参数绑定到已有变量 |

典型生命周期：

```text
用户启动程序

./server -env=prod

        ↓

flag.String注册参数

        ↓

flag.Parse()

        ↓

读取os.Args

        ↓

变量被赋值

        ↓

启动业务服务
```

在 Kafka Consumer、HTTP Server 和微服务工程中，`flag.Parse()` 通常位于启动入口 `main.go`，负责接收程序启动配置。
