> <h1 id='继承Codable的结构体'>继承Codable的结构体</h1>

```

struct CacheModel: Codable {
    
    var url:String?
    
    var startTime:Float?
    
    var maxPlayTime:Float?
    
}
```

`Codable` 是 Swift 中一个非常有用的协议组合，实际上它结合了两个协议：`Encodable` 和 `Decodable`。当一个结构体（或类）继承 `Codable` 时，它可以自动实现数据的编码（将对象转换为其他格式，如 JSON 数据）和解码（将其他格式的数据，如 JSON，转换回对象）的功能。

**具体解释**

1. **`Encodable` 协议**：提供了一种机制将结构体或类实例转换为其他格式（通常是 JSON）的数据。比如将 `HBPlayerCacheModel` 转换为 JSON 字符串。

2. **`Decodable` 协议**：提供了一种机制从其他格式的数据（通常是 JSON）转换回结构体或类实例。比如将 JSON 数据解析为 `HBPlayerCacheModel`。

<br/>

**`Codable` 的使用示例**

假设你有一个 `HBPlayerCacheModel` 实例，并希望将其转换为 JSON 数据或从 JSON 数据中创建它。

**1. 将结构体实例转换为 JSON 数据（编码）**

```swift
let playerCacheModel = CacheModel(url: "https://example.com/video.mp4", startTime: 10.0, maxPlayTime: 120.0)

if let jsonData = try? JSONEncoder().encode(playerCacheModel) {
    if let jsonString = String(data: jsonData, encoding: .utf8) {
        print("JSON String: \(jsonString)")
    }
}
```

输出结果将类似于：

```json
{
    "url": "https://example.com/video.mp4",
    "startTime": 10,
    "maxPlayTime": 120
}
```

<br/>

2. **从 JSON 数据解码为结构体实例（解码）**

```swift
let jsonString = """
{
    "url": "https://example.com/video.mp4",
    "startTime": 10.0,
    "maxPlayTime": 120.0
}
"""

if let jsonData = jsonString.data(using: .utf8) {
    if let playerCacheModel = try? JSONDecoder().decode(CacheModel.self, from: jsonData) {
        print("URL: \(playerCacheModel.url ?? "No URL")")
        print("Start Time: \(playerCacheModel.startTime ?? 0)")
        print("Max Play Time: \(playerCacheModel.maxPlayTime ?? 0)")
    }
}
```

<br/>
**总结**

&emsp; 通过让 `CacheModel` 结构体继承 `Codable` 协议，你可以轻松地将其实例转换为 JSON 数据，或者从 JSON 数据中创建该结构体的实例。这对于持久化数据、与服务器通信或在应用程序中处理数据非常有用。

> <h2 id='Codable与数据模型的转换'>Codable与数据模型的转换</h2>


1. **`Codable` 的作用**

在 Swift 里，`Codable` 是 **Encodable** + **Decodable** 的组合协议。
它的用途是 **让你的数据模型可以和 JSON / Plist / Data 等格式互相转换**。

比如你有一个 JSON：

```json
{
    "categoryId": "10001"
}
```

<br/>

如果 `DeviceCategoryInfo` 遵循了 `Codable`，你可以直接这样解析：

```swift
let json = """
{
    "categoryId": "10001"
}
""".data(using: .utf8)!

let decoder = JSONDecoder()
let info = try decoder.decode(DeviceCategoryInfo.self, from: json)
print(info.categoryId) // 输出 "10001"
```

<br/>

反过来，如果你要把模型转成 JSON：

```swift
let encoder = JSONEncoder()
encoder.outputFormatting = .prettyPrinted
let data = try encoder.encode(info)
print(String(data: data, encoding: .utf8)!)
```

✅ 总结一句：`Codable` 让网络数据解析和序列化变得非常简单，不需要自己写一堆手动 `init` 或字典解析。

<br/>

**2.`enum CodingKeys` 的作用**

`CodingKeys` 是一个 **映射规则**，告诉 `Codable`：

> JSON 的 key 和 Swift 属性名如何一一对应。

如果 **你的属性名和 JSON 字段名一模一样**，其实可以不用写 `CodingKeys`，Swift 会自动匹配。

但如果 JSON 和模型属性名不一样，就要用 `CodingKeys` 进行映射：

```swift
public class DeviceCategoryInfo: NSObject, Codable {
    public var categoryId: String?

    enum CodingKeys: String, CodingKey {
        case categoryId = "category_id" // JSON 是 category_id，Swift 用 categoryId
    }
}
```

<br/>

这样就能正确解析：

```json
{
    "category_id": "10001"
}
```

<br/>

**3.你这个例子是否必须写 `CodingKeys`？**

在你给的代码里：

```swift
enum CodingKeys: String, CodingKey {
    case categoryId
}
```

> <h2 id="Swift字符串重命名非法字符校验">Swift 字符串重命名非法字符校验</h2>

用于判断字符串是否包含设备重命名规则不允许的字符。原代码禁止：

- 空格、Tab 等 `CharacterSet.whitespaces` 字符。
- 默认以 Emoji 显示或符合特定条件的 Emoji 字符。

> 注意：`CharacterSet.whitespaces` **不包含换行符**。如果规则要求禁止所有空白和换行，应使用 `CharacterSet.whitespacesAndNewlines`。

允许：

```text
客厅摄像头
Camera01
设备_A
```

不允许：

```text
客厅 摄像头   // 有空格
Camera😀       // 有 Emoji
```

***
<br/>

> <h3 id="核心代码">核心代码</h3>

```swift
public extension String {
    var containsRenameInvalidCharacter: Bool {
        unicodeScalars.contains {
            CharacterSet.whitespaces.contains($0)
        }
        ||
        contains { character in
            let scalars = character.unicodeScalars

            return scalars.contains { scalar in
                scalar.properties.isEmojiPresentation ||
                (
                    scalar.properties.isEmoji &&
                    (scalar.value > 0x238C || scalars.count > 1)
                )
            }
        }
    }
}
```

调用方式：

```swift
let name = "Camera😀"

if name.containsRenameInvalidCharacter {
    print("非法")
}
```

`containsRenameInvalidCharacter` 是只读计算属性，每次访问都会重新执行校验：

```text
true  -> 包含非法字符
false -> 不包含非法字符
```

整体逻辑：

```text
字符串包含空白字符
        或
字符串包含 Emoji
        ↓
     返回 true
```

> <h3 id="空白字符检查">空白字符检查</h3>

```swift
unicodeScalars.contains {
    CharacterSet.whitespaces.contains($0)
}
```

`unicodeScalars` 用于遍历字符串中的 Unicode Scalar，`CharacterSet.whitespaces` 用于匹配空格、Tab 等空白字符。

例如：

```swift
let text = "A😀"

for scalar in text.unicodeScalars {
    print(scalar)
}
```

输出：

```text
A
😀
```

校验字符串 `设备 A` 时，遍历结果为：

```text
设   -> false
备   -> false
空格 -> true
A    -> false
```

只要存在一个匹配项，`contains` 就返回 `true`。

`CharacterSet.whitespaces` 可匹配：

```text
" "
"\t"
```

但不匹配 `\n`、`\r` 等换行符；换行符属于：

```swift
CharacterSet.whitespacesAndNewlines
```

<br/>

> <h3 id="Emoji检查">Emoji 检查</h3>

```swift
contains { character in
    let scalars = character.unicodeScalars

    return scalars.contains { scalar in
        scalar.properties.isEmojiPresentation ||
        (
            scalar.properties.isEmoji &&
            (scalar.value > 0x238C || scalars.count > 1)
        )
    }
}
```

外层 `contains` 按 Swift `Character` 遍历字符串；一个 `Character` 可能由一个或多个 Unicode Scalar 组成。

普通 Emoji `😀` 通常包含一个 Scalar：

```text
U+1F600
```

组合 Emoji `👨‍👩‍👧‍👦` 包含多个 Scalar：

```text
👨
ZWJ
👩
ZWJ
👧
ZWJ
👦
```

### `isEmojiPresentation`

```swift
scalar.properties.isEmojiPresentation
```

判断该 Scalar 是否默认以 Emoji 样式显示，例如：

```text
😀
😂
🔥
🚗
```

这些字符会直接返回 `true`。

---
<br/>

### `isEmoji` 与编码值过滤

```swift
scalar.properties.isEmoji &&
(
    scalar.value > 0x238C ||
    scalars.count > 1
)
```

部分普通符号也具有 `isEmoji == true`，例如 `©`、`™`，因此不能只根据 `isEmoji` 判断。原代码额外要求：

- `scalar.value > 0x238C`：过滤编码值较低的普通符号。
- `scalars.count > 1`：识别由多个 Scalar 构成的 Emoji。

例如 `😀` 的编码为 `U+1F600`，即 `0x1F600`，大于 `0x238C`，因此判定为 Emoji。

---
<br/>

### 组合 Emoji

`❤️` 通常由多个 Scalar 组成：

```text
❤
+
Variation Selector
```

此时 `scalars.count > 1` 成立，因此会被判定为 Emoji。

> <h3 id="实际示例">实际示例</h3>

### 普通设备名称

```swift
"客厅摄像头".containsRenameInvalidCharacter
```

没有空白字符和 Emoji，结果为 `false`。

### 包含空格

```swift
"客厅 摄像头".containsRenameInvalidCharacter
```

包含空格，结果为 `true`。

### 包含默认 Emoji

```swift
"Camera😀".containsRenameInvalidCharacter
```

`😀` 的编码为 `U+1F600`，且 `isEmojiPresentation == true`，结果为 `true`。

### 包含普通符号

```swift
"Camera™".containsRenameInvalidCharacter
```

`™` 可能满足 `isEmoji == true`，但其编码 `U+2122` 小于 `0x238C`，且 `scalars.count == 1`，因此结果为 `false`，允许使用。

> <h3 id="规则改进">规则改进</h3>

### 禁止换行符

原代码只检查 `CharacterSet.whitespaces`，不会拒绝 `\n`、`\r` 等换行符。如果设备名称不允许任何空白或换行，应改为：

```swift
unicodeScalars.contains {
    CharacterSet.whitespacesAndNewlines.contains($0)
}
```

完整写法：

```swift
public extension String {
    var containsRenameInvalidCharacter: Bool {
        unicodeScalars.contains {
            CharacterSet.whitespacesAndNewlines.contains($0)
        }
        ||
        contains { character in
            let scalars = character.unicodeScalars

            return scalars.contains { scalar in
                scalar.properties.isEmojiPresentation ||
                (
                    scalar.properties.isEmoji &&
                    (scalar.value > 0x238C || scalars.count > 1)
                )
            }
        }
    }
}
```

### 更严格的 Emoji 规则

如果业务明确要求禁止所有具有 Emoji 属性的字符，可以简化为：

```swift
public extension String {
    var containsRenameInvalidCharacter: Bool {
        if unicodeScalars.contains(where: {
            CharacterSet.whitespacesAndNewlines.contains($0)
        }) {
            return true
        }

        return contains { character in
            character.unicodeScalars.contains {
                $0.properties.isEmoji
            }
        }
    }
}
```

但该版本比原规则更严格，`©`、`™` 等普通符号也可能被判定为非法，是否采用应以产品规则为准。

---

| 代码 | 作用 |
| --- | --- |
| `unicodeScalars` | 遍历 Unicode Scalar |
| `CharacterSet.whitespaces` | 检测空格、Tab 等空白字符 |
| `CharacterSet.whitespacesAndNewlines` | 检测空白字符和换行符 |
| `Character.unicodeScalars` | 获取单个 `Character` 的 Scalar 集合 |
| `isEmojiPresentation` | 判断是否默认以 Emoji 样式显示 |
| `isEmoji` | 判断是否具有 Emoji 属性 |
| `scalar.value > 0x238C` | 过滤部分低编码值普通符号 |
| `scalars.count > 1` | 辅助识别组合 Emoji |

**本质：这是一个设备名称输入校验器，用于避免名称中出现业务不允许的空白字符和 Emoji。具体规则应由名称存储、传输和展示要求决定。**
